Part to Part¶

Description¶

Part to Part is a service for managing MPI data transfers between two arbitrarily partitioned sets of entities.

API¶

Create a Partition-to-Partition redistribution from global ids.

Parameters:

  • gnum_elt1 – [in] Element global ids in Part1 (size : n_part1)

  • n_elt1 – [in] Local number of elements in Part1 (size : n_part1)

  • n_part1 – [in] Number of partitions in Part1

  • gnum_elt2 – [in] Element global ids in Part2 (size : n_part2)

  • n_elt2 – [in] Local number of elements in Part2 (size : n_part2)

  • n_part2 – [in] Number of partitions in Part2

  • part1_to_part2_idx – [in]

    Index for Part1→Part2 mapping

    (for each part, size :

    n_elt1 + 1)

  • part1_to_part2 – [in]

    Part1→Part2 mapping (global ids)

    (for each part, size :

    part1_to_part2_idx[n_elt1])

  • comm – [in] MPI communicator

Returns:

Create a Partition-to-Partition redistribution from location triplets.

Parameters:

  • gnum_elt1 – [in] Element global numbers in Part1 (size : n_part1)

  • n_elt1 – [in] Local number of elements in Part1 (size : n_part1)

  • n_part1 – [in] Number of partitions in Part1

  • n_elt2 – [in] Local number of elements in Part2 (size : n_part2)

  • n_part2 – [in] Number of partitions in Part2

  • part1_to_part2_idx – [in]

    (for each part, size :

    n_elt1 + 1)

  • part1_to_part2_triplet_idx – [in]

PartToPart.iexch(k_comm, t_part1_data_def, part1_data, part1_stride=1, interlaced_str=True)¶

Initiate a non-blocking exchange (Part1→Part2)

Parameters:

  • k_comm (int) – Kind of MPI communication

  • t_part1_data_def (int) – Kind of Part1 data definition

  • part1_data (list) – Part1 data

  • part1_stride (int or list, optional) – Stride of Part1 data

  • interlaced_str (bool, optional) – Is the data interlaced? (default = True)

Returns:

Request ID (int)

Admissible values for k_comm:

  • 0 : Peer-to-peer (MPI_issend/MPI_irecv)

  • 1 : Collective (MPI_Ialltoall and alike)

Note

Additional communication kinds will be available in the future

Admissible values for t_part1_data_def:

  • PartToPart.DATA_DEF_ORDER_PART1 : Data defined according to the part1 arrays order

  • PartToPart.DATA_DEF_ORDER_PART1_TO_PART2 : Data defined according to the part1_to_part2 arrays order
